Preparación

Requisitos

Docker Desktop (o Docker Engine con Compose v2) y una terminal bash (Linux, macOS, WSL o Git Bash en Windows). Las funciones usan curl y python3 (o python) para leer JSON.

Levantar el sistema desde cero

cd Proyecto
docker compose down -v          # borra los datos: los scripts de db/ solo corren con el volumen vacío
docker compose up --build -d
docker compose ps               # siete contenedores; db y rabbitmq en (healthy)
curl -s http://localhost:8080/estado

Variables y funciones auxiliares

Todas las pruebas usan las mismas variables. Se cargan con source ../documentacion/bitacora-4/pruebas/comun.sh desde Proyecto/:

# Variables y funciones auxiliares para las pruebas de la etapa 4.
# Uso (desde Proyecto/, en bash o Git Bash):  source ../documentacion/bitacora-4/pruebas/comun.sh
# Todas las peticiones van por el gateway, como las de cualquier cliente.

B=${B:-http://localhost:8080}
PY=${PY:-$(command -v python3 >/dev/null 2>&1 && echo python3 || echo python)}
J='import sys,json; print(json.load(sys.stdin)'

# Muestra el comando (como en una terminal) y lo ejecuta. Sirve para que la evidencia
# guarde exactamente lo que se corrió y lo que salió.
paso() { echo "\$ $*"; eval "$@"; }

U=$(curl -s -X POST $B/api/usuarios -H "Content-Type: application/json" -d '{"nombre":"Prueba E4","zona":3}' | $PY -c "$J['id'])")
R=$(curl -s $B/api/restaurantes | $PY -c "$J[0]['id'])")
P=$(curl -s $B/api/restaurantes/$R/platillos | $PY -c "$J[0]['id'])")
REP=$(curl -s "$B/api/repartidores?zona=3" | $PY -c "$J[0]['id'])")

nuevo_pedido() {
  curl -s -X POST $B/api/pedidos -H "Content-Type: application/json" -H "Idempotency-Key: e4-$(date +%s%N)" \
    -d "{\"usuario_id\":\"$U\",\"restaurante_id\":\"$R\",\"platillos\":[{\"platillo_id\":\"$P\",\"cantidad\":1}]}" \
    | $PY -c "$J['id'])"
}
pagar()          { curl -s -X POST $B/api/pedidos/$1/pago > /dev/null; }
estado_pedido()  { curl -s $B/api/pedidos/$1 | $PY -c "$J['estado'])"; }
aceptar_tiempo() { curl -s -o /dev/null -w "%{http_code} en %{time_total}s\n" -X POST $B/api/pedidos/$1/aceptar \
                     -H "Content-Type: application/json" -d "{\"repartidor_id\":\"$2\"}"; }
avisos()         { curl -s "$B/api/notificaciones/pedido/$1" \
                     | $PY -c "import sys,json; [print(a['version_pedido'], a['tipo'], '|', a['mensaje']) for a in json.load(sys.stdin)]"; }
NombreQué es
BLa dirección del gateway: la única entrada al sistema.
U, R, P, REPUsuario de prueba (zona 3), primer restaurante, su primer platillo y la repartidora de la zona 3.
nuevo_pedidoCrea un pedido con una clave de idempotencia nueva y devuelve su id.
pagar, estado_pedidoPaga un pedido; muestra su estado.
aceptar_tiempoHace que un repartidor acepte un pedido y muestra el código HTTP y cuánto tardó.
avisosLos avisos que recibió el cliente por ese pedido (versión, tipo y mensaje).
pasoImprime el comando y lo ejecuta (así la evidencia guarda lo que se corrió).
En PowerShell. Las mismas pruebas se pueden hacer con curl.exe e Invoke-RestMethod; la bitácora 2 trae los equivalentes (Ciclo-Completo, Avisos, Cola, Psql). La forma más sencilla en Windows es usar Git Bash, que trae bash y curl.

curl -s -o /dev/null -w "%{http_code}\n" -X POST $B/api/pedidos -H "Content-Type: application/json" -H "Idempotency-Key: $K" -d "$CUERPO"

Además de curl, el flujo completo se probó con las dos interfaces (ver el manual de usuario):

  • Aplicación de escritorio (Proyecto/interfaz/interfaz.py): se creó un usuario, se pidieron dos aguas frescas y un caldo ($125.00), se pagó, la repartidora de la zona 3 aceptó y entregó con el código, y el cliente vio los avisos v2, v3 y v4. Con repartidores detenido, la pestaña Sistema mostró tres 503 de 1 s, luego 503 de 8 ms y la insignia del circuito en rojo.
